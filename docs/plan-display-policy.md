# 计划栏规则

每轮执行前，使用当前模型、固定分类说明、`temperature=0` 和受约束的函数参数做一次工作范围判断。它不执行实际工具，也不建立计划。依据请求语义及有限的用户对话背景分类，不以关键词、请求长度或工具调用次数判断复杂度。分类结果保存在本轮 `modelMetadata.planPolicy` 中；重新生成复用原结果，普通新问题重新判断。

| 工作范围 | 计划栏 |
| --- | --- |
| 解释、咨询、普通问答 | 不显示 |
| 已有的单一目标操作，如搜索并加载图层、定位、核对显示、查询状态 | 不显示 |
| 范围明确的单文件局部调整，如改一处文案，可包含读取与验证 | 不显示 |
| 开发功能、未知原因排查与修复、迁移、批量或相互依赖的修改、反复评估、构建发布部署及交付验证 | 必须先建计划 |
| 无法可靠判断，或范围判断未看到完整要求 | 必须先建计划核对范围 |
| 用户明确要求先制定计划 | 必须先建计划 |
| 继续已有计划的任务 | 继续使用已有计划 |

例如“加载建筑物图层并定位到郑州”是简单操作，即使需要搜索、加载、定位和检查四个工具调用；“建筑物没有显示，检查代码并修复、验证”属于复杂任务。

复杂任务首次请求只提供 `update_plan`，并强制选择该工具。执行层再次检查，成功保存计划前拒绝其他工具，即使模型或上游忽略工具选择也不会直接写文件或执行命令。计划格式错误不能解锁实际工具；模型连续两次只给文字而不建立计划时停止，保留记录。初始计划不能把尚未执行的所有阶段标为完成。计划只按实质阶段和验证证据更新，已有重复更新反馈机制仍生效。

简单任务不提供 `update_plan`，执行层拒绝额外计划调用，前端也按本轮规则隐藏计划栏。发现问题导致范围扩展时，先通过 `expand_task_scope` 引用本轮已执行的工具调用与发现，再建计划，才能开展新增工作。源码写入超出原局部调整、或扩展为多个文件时，执行层还会在新增写入前自动升级并阻止该次写入，要求先建计划。普通重试或工具次数多不会触发升级。实际工具执行和审批规则保持独立。

范围判断增加一次模型请求，其时间和用量计入本轮，范围说明不展示内部推理。它不占实际工具调用次数。分类输入有界，附件和工具返回内容不能授权操作。判断结果无效或服务不支持必要的函数调用时，在任何实际操作前报错，不默认绕过计划。自然语言分类仍依赖模型；固定分类与零温度减少差异，执行层保证分类一旦确定后严格落实。

旧回复没有本规则的元数据，保留原显示结果，不改写历史会话。
