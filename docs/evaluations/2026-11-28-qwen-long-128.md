# Qwen Coder Next — 128-round long-task evaluation

Date: 2026-11-28. Budget per response: **128 model rounds / 128 tool calls / 1800 active seconds**. Output allowance: 4096 tokens; catalog context limit: 131072. This is one fixed task used for diagnosis and targeted re-evaluation, not a reliability-rate estimate.

## Outcome

The 64K working-context run completed in **91.44 seconds**, **28 rounds**, **27 development tool calls**, with **2 summary requests**. All 17 supplied tests passed, but independent acceptance rejected a canonical idempotent retry (`.1` versus `0.10` discount rates). The original failure is retained and is **not** reported as a first-pass success.

The same Qwen session then received that concrete failure as a separately recorded repair request. It added six regression tests in `test_canonical_retry.py` and repaired the implementation in **45.48 seconds**, **13 rounds**, **11 tool calls**, with **0 new summaries**. **All 23 tests and the independent checks then passed.** Supplied tests and inputs remained unchanged. Main development plus repair used **41 development rounds and 38 tool calls**, across two separately budgeted responses; the deliberate three-read probe is separate.


**32K stress remains unsuccessful.** The final 32K build emitted a read-stall recovery hint and stopped the continuing loop, preserving the unfinished task instead of declaring success. Increasing the iteration budget alone did not make that constrained-context task reliable. The 64K result must not be represented as a 32K pass.

## Fixed task and checks

The model implemented CSV catalog validation, Decimal pricing, SQLite-backed orders, stock deductions, canonical idempotent retries, cancellation and sales reports across four modules. Seventeen supplied unit tests were immutable. Independent checks also exercised canonical retries with reordered/aggregated SKUs, discount rounding, insufficient-stock rollback, repeated cancellation, empty reports and invalid discount values; a per-run marker verified the final artifact.

Each evaluation began with a harmless identical-read probe. Keeper stopped the three repeated rounds with `no_progress`; a new message then started development in the **same session**. Forty-eight synthetic obsolete historical messages forced compaction. A deliberate missing-file read and initially failing tests exercised error handling. Neither user files nor production conversations were used.

## Fixes

- Context compaction preserves small numbered file bodies and batch results, including file hashes and failure/deferred status, instead of retaining only JSON envelope previews. Arbitrary external JSON is type-checked before treating it as numbered source lines.
- The latest complete tool-call group is preserved whenever it fits the protected prompt and hard input budget. Older history no longer forces a freshly read source file into a few dozen characters. Oversized parallel groups are still bounded; the hard context limit is unchanged.
- A derived summary plus the protected current request is not repeatedly summarized without material new history while it still fits the hard input limit. The current request remains verbatim and is excluded from redundant summarizer input.
- Runtime evidence now retains the latest 32 calls, so the displayed last eight actually stay current after long runs. Totals still cover all calls.
- Six read-only rounds that retrieve only already-seen unchanged file windows trigger a scoped recovery hint. Six further such rounds without useful progress stop with `no_progress`. New ranges, real file changes and changed test evidence allow progress; ordinary plan updates do not reset this guard. Exact three-round and two-step-cycle guards remain intact.

## Verification and evidence

300 Rust tests passed, one existing test ignored. Context and ReAct HTTP regressions passed, including an added deterministic check that newly read batch file bodies remain available through their final lines. Source hashes, prompts, CIS model revision, per-stage frozen budgets, usage, failures and independent-check output are in [the machine-readable report](2026-11-28-qwen-long-128.json). Raw stage paths are retained there. Temporary login tokens were removed and their absence checked in every evaluation database.

The isolated evaluator approves confined file writes and only the generated unittest runner for `run_tests`; arbitrary shell commands remain rejected. No rejected command was silently executed or retried with wider permissions. Generated task code was never manually patched by the evaluator. Qwen performed the separately recorded targeted repair after receiving the independent-check failure; this is not a clean first-pass sample.
