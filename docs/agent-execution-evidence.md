# 智能体分层职责与执行证据

## 目标与边界

保持 ReAct 的通用性，不根据“定位郑州”“创建文件”等关键词增加业务成果判断。
模型回复结束、工具调用成功、异步操作完成、用户目标达成是不同事实。
本机制不保证模型不再作出错误声明，也不通过额外强制工具调用制造“成功”。

## 分工

| 层 | 职责 | 不负责 |
|---|---|---|
| 智能体及 Skills | 理解需求、选择工具、制定计划、根据证据自检与回答 | 将计划或历史描述当成本轮执行事实 |
| 工具适配层 | 参数校验、执行、业务结果及异步确认 | 改写用户授权与安全策略 |
| 运行时 | 审批、调度、取消、账户与回复隔离、持久化真实调用状态 | 理解地名、判断建筑是否加载正确、判定用户目标完成 |
| UI | 显示模型文字与真实调用记录，并区分两者 | 从模型文字生成“已执行”或“已确认”徽标 |

## 工具状态与异步操作

现有 agent_runs.id 是运行时调用标识。succeeded 只说明工具调用成功；读取、加载技能、更新计划成功均不代表修改完成。
异步工具应在自身结果中提供操作关联标识和受理/执行/确认状态，并由相应状态查询或事件接口返回完成证据。
运行时不将业务返回的 accepted/saved 等状态自动提升为 completed。
地球的 cameraCommandRevision/renderedCameraCommandRevision 是现有工具级确认；不在通用运行时解释这些字段。
本轮不强制改造所有工具的业务返回格式、不新增统一后台异步作业队列。

## 执行证据 v1

从 agent_runs 按 session_id + response_id 查询实际记录，生成：
- responseId、callCount、各状态 counts。
- 最多 32 条 runId/tool/status 明细；超出时标记 truncated，计数仍完整。
- goalStatus 固定为 not_assessed，不推断任务成果。

不包含参数、命令、工具原始输出或凭证。模型每轮请求前收到最新证据，计入原有上下文预算；证据不累加到对话历史。
提示要求模型基于本轮工具返回说明结果；没有调用不意味着普通问答失败，但不能声称执行了外部操作。
本轮真实工具结果仍是业务确认依据；摘要的成功计数不能替代它们。

证据保存在当前回复 model_metadata.executionEvidence，结束（包括停止/失败）时重新生成。
原始 agent_runs 仍是权威记录，刷新/备份沿用现有机制，不增加第二套执行数据库。
UI 从当前回复的 runs 显示即时状态，避免重启后使用过期的 pending/running 快照；旧回复无证据字段时保留原始工具记录，不伪造历史确认。

## UI 语义

原“已完成”任务标题改为“回复已结束”。显示“执行记录：本轮未调用工具”或各类调用数量。
证据行只说明执行事实，不给回复判定正确/错误，不对零调用的解释性回答告警。
计划进度仍明确为模型报告；业务是否达成需由模型和用户结合实际结果判断。

## 验证

使用内存 SQLite 和隔离的本机模拟模型，验证零调用、多步调用、失败/待批准状态、历史回复与会话隔离、摘要边界、持久化及 UI 状态。无需真实模型密钥。

本轮本机验证：2 项证据单元测试、test-react-http.py 模拟模型全流程、test-react-ui.cjs DOM 回归均通过；涵盖证据入模、零调用、三次工具调用、重新生成与刷新、停止和恢复。调试构建成功，127.0.0.1:4301 已更新启动并通过 HTTP 检查。没有使用真实模型进行成功率评测，也未宣称能拦截所有虚假完成声明。
