# 本机发布回归

2026-11-22，Linux x86_64。此流程不发布安装包、不请求真实模型服务。

## 执行

先执行 `cargo test` 和 `cargo build`，然后：

```sh
NODE_PATH=/tmp/keeper-ui-check/node_modules python3 scripts/test-release-local.py
```

NODE_PATH 指向本机已安装 jsdom 的 node_modules。运行器为每项设置 240 秒超时，输出独立日志及 JSON 报告到 `/tmp/keeper-release-regression-*/`，任何失败返回非零状态。

## 覆盖

- Linux 实际程序替换、健康检查失败回滚；带空格的安装路径；升级前后数据库草稿保留。
- 删除新列/新表模拟旧数据库，连续两次启动验证迁移幂等；会话、草稿和 MCP 配置保留；未完成工具标记中断，不重放。
- 文字草稿随版本4备份恢复为新会话，保留原会话；兼容版本1–3；拒绝超长草稿及格式版本不一致。
- 账户范围、校验和、引用校验、事务回滚、消息版本关系、大文件备份、附件/MCP 图片及审批不可重放。
- 账户切换立即清理界面和草稿，旧异步响应不能恢复上一账户数据。
- MCP 断线、停止与迟到响应；浏览器连接恢复后重新读取会话；账户变化时重新加载，不重放生成或工具请求。
- 插件配置安装、权限和账户隔离；Agent、备份、草稿界面回归。

## 验证边界

迁移使用临时数据库中的旧结构夹具，升级使用本机测试程序；不等同于所有历史安装版本的兼容认证。浏览器重连使用自动化事件模拟，MCP 使用本地测试服务。Windows、ARM、macOS 原生升级和运行未验证；生产 CIS 数据迁移及真实模型连通性未验证，须在对应环境另行执行。跨平台 TODO 保持未完成。
